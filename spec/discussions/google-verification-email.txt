It now states, under these headings:

- "Google user data we receive" and "How we use it, per permission": how zippp

  names of the one sheet the user connects and writes the rows the user accepts.
  zippp never reads the data rows. drive.file finds or creates the zippp
  spreadsheet, and only files zippp created or the user picked are visible.

  we do not use it for advertising or to train AI models.
- "How we protect it": the data protection mechanisms, including TLS in transit,
  AES-256-GCM encryption of OAuth tokens at rest with a key held only in server
  environment variables, least privilege scopes, and server-side admin checks.
- "Limited Use": the Google API Services User Data Policy statement, including
  the Limited Use requirements.

3. AI integration: Option 2, complete data segregation

- The AI step receives only the receipt photo the user takes with the camera, or
  text read from that photo. The photo is not Google user data.
- It never receives Google account data, a spreadsheet id, sheet contents, or a
  Drive file.
- The extraction code path does not load a Google token, and the sheet code path
  does not import an AI module.
- An automated test in our build fails if the photo path imports a Google data
  module, if the extraction endpoint accepts any field other than the image, or
  if the sheet endpoint imports an AI module.
- Analytics autocapture and session recording are disabled. OAuth refresh and
  access tokens are encrypted at rest.
- The video shows the extraction payload at 2:20: OCR text only, no Google data.
