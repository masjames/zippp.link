## 1. Why this revision

zippp was specified for one persona (Charlie, F&B owner). The product now
serves four. Two of them (Fais, Bagas) scan a different kind of document and
need a different sheet shape. The sheet itself is the deliverable, and today it
is an unstyled single tab with no totals and no proof photo.

| Persona | Scans | Row meaning | What they open the sheet for |
|---|---|---|---|
| **Sonny**, purchasing staff at a resto | supplier nota (money out) | purchase line | owner checks who bought what, per outlet |
| **Bibian**, college student | store receipt (money out) | expense line | spend per day, per category |
| **Fais**, seller recapping sales on paper | his own sales nota (money in) | sale line | **daily recap total** per month |
| **Bagas**, staff claiming reimbursement | personal receipts (money out, to be repaid) | claim line | one month = one claim, with **photo proof** |

Decisions taken (2026-10-13):

1. Template = persona. Four named templates plus `custom`.
2. One spreadsheet per user. **One tab per month**, named by **receipt date**.
   Tabs older than 12 months are **hidden**, not moved.
3. **Daily totals** live in a formula block on the right of each month tab, plus
   a `Summary` tab. zippp never writes a total.
4. Bagas: **no status workflow.** Proof = the nota photo stored in the user's
   own Drive, linked from the row. Month tab = the claim. Sharing uses a month
   export (section 5.4).
5. Credits: 30-day expiry stays. Indonesia: **Rp 15.000 = 100 scans** is the
   entry preset.
6. Deliverable: this audit first, then patch the docset (section 9), then build
   in the order of section 10.

## 4. Sheet layout (zippp-owned templates)

### 4.1 Structure

```
[zippp] <Template name>
├── Summary       first tab. Month | Receipts | Total. One row per month tab.
├── 2026-10       current month
├── 2026-09
├── ...           12 most recent months visible
└── 2025-09       older than 12 months: hidden (sheet property hidden=true)
```

- Tab name `YYYY-MM` from the **receipt date** (after the client's assumed-date
  fill, so it is never empty).
- On Accept, `append` resolves the tab. If it does not exist: create it with
  headers, formatting, validation and the daily block in one `batchUpdate`,
  then add the Summary row, then hide any tab older than 12 months. Then append.
- `custom` template: tab = `workspace.sheet_tab`, as today. No Summary, no block.
- Existing `resto-inventory` and `personal-expense` workspaces created before
  this revision keep writing to their single tab until the user creates a new
  sheet. No migration.

### 4.2 Formatting (applied per tab at creation)

| What | Value |
|---|---|
| Header row | bold, background brand colour, text ink, frozen, filter on |
| Date columns | `yyyy-mm-dd` |
| Money columns | `#,##0` for IDR, `#,##0.00` otherwise (decide from region at create time) |
| Qty | `0.##` |
| Column widths | Date 100, text 180, money 110, Photo 70, Receipt ID 120 |
| Banding | alternate row colour, light |
| Photo cell | hyperlink formula, text "photo" |
| Daily block header | bold, same fill as row 1 |
| Tab colour | current month brand colour, older grey |

Constants (hex, widths, formats) live in `src/lib/google/sheet-style.ts`. No
magic numbers in `sheets.ts`.

### 4.3 Daily block (per month tab, right of the data, 2 empty columns gap)

Rows pre-filled for every day of that month at creation, so no `UNIQUE`/`SORT`
is needed and empty days show 0.

| Day | Receipts | Total |
|---|---|---|
| 2026-10-01 | `=COUNTUNIQUEIFS(<ReceiptID>, <Date>, A2)` | `=SUMIF(<Date>, A2, <Amount>) + SUMIF(<Date>, A2, <Tax>)` |
| ... | ... | ... |
| **Month** | `=SUM(...)` | `=SUM(...)` |

`<Amount>` is `Line amount` (T1) or `Amount` (T2, T3, T4). Because `Tax` is on
the last line only, amount + tax per day equals the sum of receipt totals when
every line has an amount. If a line has no amount the day undercounts; this is
accepted and matches the "never invent" rule.

### 4.4 Summary tab

| Month | Receipts | Total |
|---|---|---|
| 2026-10 | `='2026-10'!<MonthReceipts>` | `='2026-10'!<MonthTotal>` |

zippp appends one Summary row when it creates a month tab. Newest month on top.

### 4.5 Photo proof (T4 on by default, T1 opt-in in Settings)

- Drive folder `[zippp] Receipts/YYYY-MM/`, created with `drive.file` scope
  (already granted). File `YYYY-MM-DD <merchant or nota> <scanId first 8>.jpg`,
  the same downscaled JPEG the client already holds in IndexedDB.
- Flow on Accept: client sends `multipart/form-data` (`receipt` JSON, `scanId`,
  `staff`, `outlet`, ops, `image` only when the template has photo on). Server:
  spend credit, upload image, append rows with the link, respond. If append
  fails, trash the file and refund. If upload fails, append without the link
  and return `photo: "failed"`; the card shows a soft notice, no retry loop.
- Privacy: the photo goes to the user's own Drive. zippp still keeps no copy.
  `SPEC.md` "no server-side image store" stays true; wording and the privacy
  page gain one sentence: "If photo proof is on, the photo is saved to your
  Google Drive."

### 4.6 Per-month export and share (Bagas)

Phase A (this revision): the month tab plus the Drive folder is the export. In
the connected view and on the card's **Saved** toast, `Open this month` opens
the spreadsheet at the current month tab (`#gid=`). Sharing is Google's own
Share button. Zero code beyond the deep link.

Phase B (later, `LATER.md`): `Share month` in the app. Server fetches
`/export?format=pdf&gid=<tab>` with the user's token, returns the PDF, client
uses the Web Share API, falls back to download. Not in this revision.

## 7. Architecture notes for the implementer

- All Sheets structure work goes through one new module
  `src/lib/google/sheet-layout.ts`: `ensureMonthTab(spreadsheetId, template,
  yyyymm, region)`, `hideOldTabs(spreadsheetId, keepMonths = 12)`,
  `summaryUpsert(...)`. It composes `batchUpdate` requests; `sheets.ts` keeps
  the HTTP helpers. Formatting constants in `sheet-style.ts`.
- Drive upload in `src/lib/google/drive.ts`: `ensureFolder(path[])`,
  `uploadJpeg(folderId, name, bytes)`, `trashFile(id)`. Multipart upload,
  `drive.file` scope.
- `append` route order: validate → spend (idempotent on scan id) →
  ensureMonthTab → upload photo (optional) → append → respond. Any throw after
  spend refunds (already the pattern).
- `ensureMonthTab` must be safe under concurrent Accepts: read the spreadsheet
  meta, and on `addSheet` 400 "already exists" re-read and continue.
- Workspace config gains `photo_proof: boolean`, `ops_defaults: Record<string,
  string>` (default outlet moves here, keep `default_outlet` as read fallback).
- No change to the extraction pipeline in this revision.
- Constants: `LOW_CREDITS_WARN`, `KEEP_VISIBLE_MONTHS = 12` in
  `src/lib/billing/config.ts` and `sheet-style.ts` respectively.
