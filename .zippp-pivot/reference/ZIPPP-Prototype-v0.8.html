React Native implementation

Recommended: Expo + Expo Router + Tamagui 3, using ZIPPP-owned components for headings, monetary figures, transaction rows, contextual actions, forms, and navigation. Use native controls where platform conventions matter.

Additional capabilities: camera viewfinder and native capture, Expo SQLite (local records; verify platform persistence details), FlashList (long transaction histories), and optional Expo UI for native-specific controls. This HTML is an interactive design prototype, not production React Native code.

Data ownership & synchronization

Google Sheets is the authoritative ledger for approved transactions. Captured receipt images and pending drafts belong in the user's Google Drive even before review, while pending records are also stored in an encrypted local queue. Upstash Redis caches a short-lived, encrypted dashboard snapshot of confirmed records only.

Production requirement, not a connected service in this prototype. Google sync is not performed; the sync control never claims cloud success. Browser local storage here is not encrypted, so do not upload real receipts. Readable Sheets cells cannot simultaneously be end-to-end encrypted ciphertext.
