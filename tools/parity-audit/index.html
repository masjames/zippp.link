Gap 6A — Credit count vs quota % (Critical)

  • Web: shows raw 42 kredit + "Isi ulang kredit" button.
  • Android: shows quota % progress bar — no raw count, no top-up button.
  • Spec (FEAT-118 §5): Android should show %. Web should eventually migrate. This creates user confusion.

Gap 6B — Android missing: Telegram, Language, Referral, Devices (Critical)

  • Telegram: Web connects bot; Android has no Telegram section at all.
  • Language: Web allows locale switch; Android uses system locale.
  • Referral: Web shows referral code; Android has none.
  • Devices: Web lists connected devices + pairing code generator; Android has none.
  • Some of these are spec-intentional (Android = lean); others may be spec gaps.

Gap 6C — Sheet disconnect missing on Android

  • Web: "Putus koneksi sheet" button in Settings > Sheet.
  • Android: only shows "Buka Lembar" (open in browser). No disconnect.
  • Users cannot re-connect to a different Sheet from Android Settings.

Gap 6D — Notification capture toggle (Android only)

  • Android: "Aktifkan tangkap via notifikasi" toggle in Settings.
  • Web: no equivalent (web cannot receive push notifications for capture).
  • This is by design — Android-only feature.

Android
No billing / top-up UI on Android. DEC-002: Android billing deliberately excluded. Rationale: Paddle/DOKU SDKs not integrated on Android. Play Billing not in scope. Android users who need to top up must use the web app at zippp.link. Note: Android Settings shows quota % bar only; no "Isi ulang" button appears anywhere on Android.

By design — DEC-002: No Android billing

  • Web: full DOKU + Paddle billing flow with order history at /app/topup/order/[id].
  • Android: explicitly excluded. No top-up button, no billing screen.
  • Users are directed to web for any credit purchase.
  • UX note: Android should show a clear message pointing to zippp.link when credits are low, rather than silently failing.
